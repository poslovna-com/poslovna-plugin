# Before you publish any of this

An agent restating a register fact in a document can be a **redistributor** in a way a browser
page is not. The rights are not uniform across sources, so there is no single answer to "may I
republish this".

**Read `poslovna://catalog/sources` first.** It lists every source with its attribution string
and what may be republished. It is a resource, not a tool call, and it is cheap.

Three rules that hold regardless:

**Attribute the register, not us.** The authority is the register and its publication; poslovna
is the channel. Where a per-record source link exists, official registers link to their own
document — use that link. Aggregators never do, and a few sources genuinely have no per-record
link.

**Cite the as-of date.** A register extract is a snapshot. A statement about a company's status
with no date attached will be wrong eventually and unfalsifiable immediately.

**Keep the qualifier on inferred data.** Where an identity was matched by a model rather than
named by the register, the confidence is part of the fact. Publishing the match without it turns
a probabilistic link into an assertion about a named person.

## Personal data

Named natural persons appear in several of these registers, lawfully, because the registers
publish them. That does not make every use lawful.

- Officer, member and beneficial-owner names are published by the registers themselves.
- Some person-level material is deliberately **not** served, and its absence is a decision rather
  than a gap. Do not attempt to reconstruct it from adjacent facts.
- Never infer or publish a sensitive characteristic — ethnicity, health, politics, beliefs —
  against a named person from any of this data. Names and addresses do not license that
  inference, and it is a special category under GDPR Article 9.

If a request asks you to assemble a profile of a private individual rather than to check a
counterparty, that is the point to say so.
